# 졸업전시 팀 작업실

리비두비·룸의 할 일, 컨펌·전시 일정, Figma·Google Drive 링크를 관리합니다.

## 팀 접속

이메일·비밀번호 가입 없이 **초대 링크 → 이름 선택 → 바로 작업**합니다. 같은 브라우저에서는 다시 들어와도 세션이 유지됩니다. 이름은 프로필·담당 작업 표시용이며 본인 인증이 아닙니다.

초대 링크는 접근 권한 자체입니다. 팀 밖에 게시하지 마세요. 링크를 가진 사람은 공유 작업실을 수정할 수 있습니다. 일반 사이트 주소만 아는 사람이나 초대받지 않은 익명 세션에는 DB 읽기·쓰기를 허용하지 않습니다. 브라우저 저장 데이터를 지우거나 ‘이 브라우저에서 나가기’를 누르면 다시 초대 링크가 필요합니다.

Supabase 익명 Auth가 브라우저별 세션을 발급하고, DB의 해시 기반 초대 확인 RPC가 멤버십을 만듭니다. RLS는 이 멤버십과 현재 초대 버전을 확인합니다. 초대 키 해시·멤버십 테이블은 브라우저에서 직접 읽거나 수정할 수 없습니다. 원본 초대 키는 소스 코드·빌드·공개 저장소에 넣지 않습니다.

초대 링크 회수 시 관리자가 새 키 해시와 증가한 version을 적용하면 기존 링크와 기존 멤버십이 무효가 됩니다. 새 링크를 팀에 다시 안내해야 합니다. 운영자는 사용자별 접근 해제·키 회전을 DB에서 관리합니다. 익명 Auth의 남용 방지를 위해 Supabase rate limit을 유지하고, 공개 범위가 커지면 CAPTCHA를 별도로 설정하세요.

## 사용 흐름

- 홈: 다음 컨펌·전시 D-day, 프로젝트별 이번 컨펌까지 할 일, 작업 자료.
- 작업 현황: 전체 프로젝트·리비두비·룸, 미완료·완료·전체, 담당자를 함께 필터링합니다.
- 전체 일정: 시작일·종료일이 있는 주요 일정과 작업 마감, 주간·월간 캘린더.
- 자료실: 프로젝트별 Figma·Drive URL 등록·수정·새 창 열기.
- 설정: 삭제한 항목 복원, 백업 내려받기, 브라우저 접근 해제.

홈은 미완료 우선·마감일순으로 프로젝트당 최대 8개를 표시합니다. 여백·행 간격은 유지하고 카드 높이가 자연스럽게 늘어납니다. 작은 화면에서는 페이지가 스크롤됩니다. 9개 이상이면 ‘더 보기’로 해당 프로젝트의 전체 작업을 엽니다. 선택한 프로젝트에서 작업을 추가하면 프로젝트가 미리 선택됩니다.

작업 추가는 작업명·프로젝트·마감일·복수 담당자를 입력하는 한 가지 방식입니다. 담당자 미정도 가능하며 링크는 선택 항목입니다. 이유진·임다혜·윤서영·강주원의 이름 아바타를 사용합니다. 사진은 임의 생성하지 않습니다. AI 분류·API 키 입력·예시 보기·파일 업로드는 없습니다. 기존 demo 레코드는 보존하되 사용자 화면에서 제외합니다.

완료 체크 시 한국 시간 완료 날짜를 저장합니다. 프로젝트/공통 컨펌이 종료된 다음 날 그 컨펌일까지 완료한 작업은 홈에서만 숨깁니다. 완료·전체에서는 계속 보관하고 다시 열 수 있습니다. 지난 마감 작업을 오늘 완료해도 즉시 숨기지 않습니다. 기존 완료 날짜 없는 기록은 마감일 기준입니다. 미완료 작업은 기한이 지나도 유지합니다.

일정 기간은 양 끝 날짜를 포함합니다. 컨펌 기준일은 시작일, 전시·마일스톤 기준일은 종료일입니다. 개별 작업 마감은 일정 변경과 별개입니다. 기존 일정 연결 작업은 연결을 유지하고, 마감일을 직접 바꾸면 개별 날짜로 전환됩니다.

## 저장·동시 수정·복구

Supabase Postgres에 공유 저장하고 Realtime과 4초 갱신을 사용합니다. 서로 다른 변경은 자동 병합하고, 같은 필드 충돌은 입력을 유지한 채 최신 내용을 확인하도록 안내합니다. 빠른 연속 체크는 큐로 모두 처리합니다.

삭제는 소프트 삭제이며 삭제한 항목에서 복원할 수 있습니다. 일정 삭제 시 연결 작업의 기존 마감일을 개별 날짜로 보존합니다. DB 변경 전 100버전을 보관합니다. 이는 같은 DB 안의 실수 복구용이며 외부 재해복구 백업을 대체하지 않습니다.

오프라인 자동 동기화는 지원하지 않습니다. 저장 실패를 성공으로 표시하지 않고 입력·재시도를 유지합니다. 외부 Figma·Drive 권한은 해당 서비스에서 확인합니다.

## 개발·배포

Node.js 22 이상: `npm ci`, `npm start`. 로컬 주소는 http://127.0.0.1:4173 입니다.

공개 접속 설정은 `public/cloud-config.json`의 프로젝트 URL·공개 publishable/anon 키입니다. 이 키는 브라우저 공개용이며 보안은 RLS와 비공개 초대 키로 보장합니다. service-role·sb_secret·관리 토큰은 절대 넣지 않습니다.

GitHub Pages는 `npm run build:pages`로 정적 화면을 배포합니다. Actions가 테스트 성공 후 배포하며 클라우드 설정이 없거나 서버 전용 키가 있으면 빌드를 거부합니다. 기존 환경 변수로 덮어쓰는 로컬 개발도 지원합니다. GitHub 배포는 저장소의 공개 설정을 기준으로 빌드합니다.

새 DB에는 다음 마이그레이션을 순서대로 적용합니다.

1. `supabase/migrations/202610190001_workspace_hardening.sql`
2. `supabase/migrations/202610190002_invite_access.sql`

`supabase/config.toml`은 익명 로그인 활성화만 선언합니다. `supabase config diff`로 검토한 뒤 `config push`하면 선언하지 않은 서비스 설정은 유지합니다.

DB 작업은 로컬에 로그인한 Supabase CLI를 사용합니다. 초대 키는 관리자가 안전하게 생성하고 SHA-256 해시만 `workspace_access`에 저장합니다. 기본 상태를 초기화하거나 기존 공유 데이터를 덮어쓰지 마세요.

이 컴퓨터의 기존 JSON 작업실을 별도로 실행하려면 `WORKSPACE_LOCAL_ONLY=1 npm start`를 사용합니다. 이 모드는 다른 기기와 공유되지 않습니다. `data/workspace.json` 및 변경 전 백업 100개를 사용합니다. 익명 공유 모드와 로컬 모드는 자동으로 양방향 동기화되지 않습니다.

## 검증

- `npm test`: 격리된 모델·Postgres·Chrome 테스트. 실제 DB를 변경하지 않습니다.
- `npm run build:pages`: 배포 산출물 확인.
- `node scripts/verify-cloud.mjs --run-live`: 명시적 실DB 검사. 숨긴 QA 레코드만 생성·회수합니다.
- `node scripts/verify-cloud-browser.mjs --run-live`: 실제 클라우드 브라우저 진입·세션 유지·조회 검사.

라이브 검사는 로컬의 비공개 `data/cloud-access.json`이 필요합니다. 이 파일과 원본 초대 키·사용자 데이터는 Git에서 제외합니다. macOS에서는 설치된 Chrome, CI에서는 Playwright Chromium을 사용합니다. 상세 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.

범위: 한 팀·한 공유 작업실용입니다. 여러 팀 격리, 역할별 권한, 오프라인 자동 저장, iOS Safari 물리 기기 검사는 별도 범위입니다.
